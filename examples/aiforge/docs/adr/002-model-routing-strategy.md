# ADR-002: 模型路由策略设计

**状态**: 已采纳  
**日期**: 2026-06-02  
**作者**: XXX  
**关联**: gateway/services/router.py

---

## 背景

AIForge 同时拥有本地部署的 Qwen3:9b（Ollama）和云端 DashScope API，
需要设计一套路由策略，在成本、隐私、性能之间取得平衡。

---

## 核心矛盾

| 维度 | 本地模型 | 云端模型 |
|------|---------|---------|
| 成本 | 零 API 费用 | 按 Token 计费 |
| 隐私 | 数据不出本地 | 数据上传到云端 |
| 能力 | 受限于 9B 参数 | 旗舰模型能力 |
| 延迟 | 受本地 GPU 限制 | 网络延迟 |
| 可用性 | 依赖本地环境 | 依赖网络和配额 |

---

## 路由规则设计（优先级从高到低）

### 规则 1：模型名显式指定
用户在请求中指定具体模型名时，直接路由，不做额外判断。
```
qwen3:9b / local → 本地
qwen-plus / cloud / gpt-4 → 云端
```
**理由**: 用户显式意图优先级最高。

### 规则 2：无云端 Key → 强制本地
环境变量 `DASHSCOPE_API_KEY` 未配置时，所有请求走本地。
**理由**: 安全降级，避免因配置问题导致服务不可用。

### 规则 3：长上下文 → 云端
消息估算 token 数超过 3000 时，自动切换云端。
**理由**: Qwen3:9b 处理长上下文时质量下降明显，云端旗舰模型表现更稳定。

### 规则 4：默认 → 本地
**理由**: 成本优先 + 隐私优先，符合企业部署的默认诉求。

---

## Token 估算方法

采用简单估算：`字符数 ÷ 4 ≈ Token 数`

精确 Token 计数需要加载 Tokenizer（额外依赖 + 延迟），对于路由决策来说，
粗略估算已足够（误差在 20% 以内，不影响阈值判断）。

---

## 未来扩展点

以下场景暂不实现，预留扩展接口：
- **负载均衡**: 本地模型并发满时自动溢出到云端
- **成本熔断**: 当月云端费用超阈值，强制降级本地
- **A/B 路由**: 按比例分流，用于模型效果对比
- **租户级策略**: 不同租户配置不同的路由偏好
