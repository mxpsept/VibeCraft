# Rules: 企业级规范

> 适用范围：所有企业级项目通用。与具体技术栈无关，可跨项目复用。
> 优先级：最高。其他层级的规则不得与本文件冲突。
> 📌 使用说明：根据行业特性在【行业定制区】补充专属内容。

---

## 安全规范

### 密钥与凭证
```
✅ 所有密钥通过环境变量注入，从不硬编码
✅ .env 文件加入 .gitignore，提供 .env.example
✅ API Key 存储必须加密（AES-256 或 bcrypt hash）
✅ 日志中屏蔽敏感字段（key、password、token、secret）
❌ 不在 URL 参数中传递密钥
❌ 不在前端代码中暴露后端密钥
❌ 不在错误信息中返回内部实现细节
```

### 接口安全
```
✅ 所有 API 必须经过鉴权中间件
✅ 使用 HTTPS（生产环境强制）
✅ 敏感接口加速率限制（Rate Limit）
✅ 输入参数严格校验（Schema 验证）
✅ SQL 操作使用参数化查询，禁止字符串拼接
❌ 不信任客户端传来的用户 ID / 租户 ID（服务端从 token 解析）
```

### 数据隔离
```
✅ 多租户系统：数据库查询必须带 tenant_id 过滤
✅ 用户只能访问自己租户的数据
✅ 管理员操作需记录审计日志
✅ 敏感数据字段加密存储
```

## 日志规范

### 必须记录
```
- 所有 API 请求：时间、路径、方法、状态码、耗时
- 鉴权事件：登录、登出、权限变更
- 数据变更：操作人、操作内容、操作时间
- 错误事件：完整 stack trace（不对外暴露）
```

### 日志格式（JSON 结构化）
```json
{
  "timestamp": "ISO8601",
  "level": "INFO|WARN|ERROR",
  "service": "{{service-name}}",
  "tenant_id": "string",
  "user_id": "string",
  "event": "domain.action",
  "data": {}
}
```

### 禁止记录
```
❌ 不记录密码、API Key 明文
❌ 不记录完整的用户隐私数据
```

## 错误处理规范

### 统一错误响应格式
```json
{
  "code": "BUSINESS_ERROR_CODE",
  "message": "用户友好的错误描述",
  "detail": "可选的详细信息",
  "request_id": "req_xxx"
}
```

### HTTP 状态码规范
```
200 成功
201 创建成功
400 客户端参数错误（附错误码和描述）
401 未鉴权
403 无权限
404 资源不存在
408 请求超时
429 触发限流（附 Retry-After header）
500 服务端错误（只返回 request_id，不暴露细节）
```

## 合规规范

### 数据保留
```
操作日志：90 天
业务数据：按法规要求（默认 3 年）
用户行为数据：7 天
日志定期归档，过期自动清理
```

### 审计要求
```
✅ 所有数据变更操作可追溯
✅ 删除操作采用软删除（is_deleted 标记）
✅ 批量操作记录操作人和时间
✅ 提供数据导出接口
```

## 可用性规范
```
核心接口超时：10s
数据库连接池：最大 20，最小 5
缓存穿透防护：空值缓存 60s
熔断策略：连续 5 次失败触发，30s 后恢复探测
```
